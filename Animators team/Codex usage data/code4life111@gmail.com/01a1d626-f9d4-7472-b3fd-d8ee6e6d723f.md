## Assistant (started 2026-11-13T18:24:46.56Z)

    **A useful Three.js preview workspace is a medium feature: roughly 2–4 developer-weeks for a first production version.** Adding the renderer is straightforward; model intake, saved state and Planner integration take most of the work.
    
    Assuming you mean loading 3D models or animations, moving around them and inspecting playback:
    
    | Scope | Estimated effort* |
    |---|---:|
    | Proof of concept: load a GLB, orbit camera, play animation | 1–2 days |
    | Reliable viewer: playback/scrubbing, lighting, loading errors, large-model handling | 5–10 days |
    | Planner workspace: uploads, saved sessions/views, project or shot links, permissions, thumbnails and verification | 10–20 days |
    | Previz authoring: arrange objects, edit cameras/lenses, undo, keyframes and frame-accurate video export | 6–12+ weeks |
    
    *Total effort per scope, not additive; one experienced developer, with representative models available. These are preliminary estimates.*
    
    The Planner already has workspace navigation, authentication, storage and media infrastructure we can reuse. **There is also an existing, unbuilt Three.js proposal** in the [Animatic creation plan](/E:/YH_Tools/YHAP/Feature%20plans/Animatic%20creation%20tab%20plan.md:553): imported models, object placement, camera lenses and still/depth/normal exports. It can be developed separately from the AI generation features.
    
    I would start with **GLB models and their included animations**, one reusable viewer engine, and a workspace that saves references and viewing settings. Three.js already provides a [glTF loader with scenes, cameras and animation clips](https://threejs.org/docs/pages/GLTFLoader.html). FBX intake needs a separate allowance for conversion and checking real studio files; its [browser loader has documented limitations](https://threejs.org/docs/pages/FBXLoader.html).
    
    The largest estimate changes would come from:
    
    - **Asset fidelity:** prepared preview models versus production Unreal assets and materials.
    - **Interaction:** inspecting existing animation versus editing poses, objects and camera animation.
    - **Output:** screenshots versus exact-frame clips that become animatic media.
    
    One existing decision matters: the Assets library currently **does not serve FBX bytes**, and its viewer was closed on that basis ([AW-D10/AW-D17](/E:/YH_Tools/YHAP/Feature%20plans/Asset%20workspace%20plan.md:551)). Connecting this to SVN library assets would require revisiting that policy; a separate GLB-upload workflow could avoid that dependency.
    
    **Is the intended workspace mainly for inspecting existing models and animations, or for composing and animating shots inside Planner?**

It could exhaust memory during validation or viewing. Define decoded-memory limits or reject sparse accessors in v1. [Plan location](</E:/YH_Tools/YHAP/Feature plans/3D workspace plan.md:107>), [glTF specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#sparse-accessors).
    
    2. **P2 — Republishing can mix old descriptions with a new scene.** A viewer fetches presentation A, the owner publishes B, then the model URL returns B’s geometry. Model requests need the expected publication version and must reject mismatches. [Plan location](</E:/YH_Tools/YHAP/docs/superpowers/plans/2026-11-13-3d-workspace-v1.md:90>).
    
    3. **P2 — Successful upload retries can leave the editor stranded.** The existing queue’s completion promise settles once. After failure → Retry → success, the queue can show Done without giving the editor the new model descriptor. The plan needs a recoverable upload-result lookup, including after leaving and reopening the editor. [Plan location](</E:/YH_Tools/YHAP/docs/superpowers/plans/2026-11-13-3d-workspace-v1.md:193>).
    
    4. **P2 — The creation guard conflicts with the chosen test environment.** The prescribed guard returns no user in dev-open mode, even after signing in, while the planned authoring test runs in that mode and requires an owner.
