## Assistant (started 2026-10-18T12:09:50.908Z)

    Research is complete, including **a new rail with no backward-compatibility requirement**. Full findings: [YH Rail NURBS research](E:/SVN/YH_Create/docs/YH_Rail_NURBS_Research_2026-10-18.md).
    
    | Option | Main benefit | Main limitation |
    |---|---|---|
    | **External driver** for existing rails | Adds polygon editing while retaining existing mounts, travel keys and behavior | Weighted NURBS requires approximation |
    | **New actor generating an Unreal spline** | Cleaner, unified editing interface | Retains the same curve-representation limit |
    | **New native NURBS rail** | Direct weighted NURBS evaluation and native Bézier sections | Needs its own distance mapping, orientation and integrations |
    
    The key finding is that **the control-polygon workflow does not require weighted NURBS**. Equal-weight cubic B-splines can convert exactly into ordinary cubic segments. General weighted NURBS cannot. [Mathematical basis](https://pages.mtu.edu/~shene/COURSES/cs3621/NOTES/spline/NURBS/NURBS-def.html)
    
    **Bézier and polygon editing can coexist**, using either explicit mode switching or separate sections—for example, a NURBS approach followed by a hand-tuned Bézier turn. Independently editing both representations of the same section needs additional constraints.
    
    My recommendation:
    
    - **Fastest improvement to current production:** external cubic B-spline driver.
    - **Strongest independent next-generation rail:** native NURBS/Bézier rail, with ordinary spline export as an optional bridge.
    
    The report also covers live dragging, undo, timing changes, Formation/Pilot/Naval dependencies, and unfinished UE 5.8 B-spline APIs.
