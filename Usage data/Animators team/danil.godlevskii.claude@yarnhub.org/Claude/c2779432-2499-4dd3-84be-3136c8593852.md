## Assistant (sent 2026-10-25T17:57:44.606Z)

    I audited the Me 262 blueprints with the editor closed, on `anim_0253` r1342; nothing was changed. There are two separate problems. Six variant BPs fail to compile. The main BP compiles, but it is heavier than the B-25 was before we optimised it, and its editor logic makes the cost worse.
    
    ## 1. Six blueprint versions are broken
    
    `BP_0253_Me_262_Basic`, `_Black11`, `_Green4`, `_White8`, `_DMG_V1` and `_DMG_V2` all fail to compile. When spawned, each one is an empty actor with only the default billboard.
    
    - **Main cause: a struct was moved without a redirector.** These six BPs still point at `/Game/ObjectLibrary/Other/PlanesGunSystem/Blueprints/S_GunData`. That struct now lives at `/Game/StudioTools/PlaneGunSystem/Structure/S_GunData`, most likely moved in the r1190 merge, and nothing was left behind at the old path. Every node that reads the gun data fails with "No Struct in Break <unknown struct>" and "In use pin S Gun Data no longer exists".
    - **They also use the old 0242 animation rig.** Their AnimBP is `ABP_Me_262_0242`, built for `SKEL_Me_262_0253_OLD` (17 bones), while their mesh is `SK_Me_262` on `SKEL_Me_262` (41 bones). Their Control Rig `Me_262_242_CtrlRig` is set up against the old 0242 mesh. So even after the struct is fixed, the control surfaces would not animate.
    - **They reference a blueprint that's gone.** All six point at `BP_Spitfire_Mk1a_0240`, which no longer exists.
    - **They are probably obsolete.** The working `BP_0253_Me_262`, which all three shots spawn, has a variant enum (Basic / Black 11 / Green 4 / White 8 / DMG) and picks the hull mesh and material itself. It already covers what the six variants were for.
    
    ## 2. Why the editor stutters when a plane is animated
    
    All figures are per plane, measured on `BP_0253_Me_262`:
    
    | Component | Triangles | Notes |
    |---|---|---|
    | `SK_Me_262` hull (skinned) | 943,058 | 1 LOD, Nanite off |
    | 24 × `SK_R4M_Rocket` (skinned) | 24 × 27,624 = 663k | each rocket is its own skeletal component |
    | `SK_Me_262_Stick` (skinned) | 47,736 | |
    | `SM_Me_262_Engine` (static) | **2,672,174** | larger than the whole hull, 1 LOD |
    | Rocket bases, gauge arrows, pedals | ~124k | |
    | **Total** | **≈ 4.45M** (1.65M skinned) | the B-25 was ~3.3M before optimisation |
    
    It's the same pattern as the B-25, plus some extra problems:
    
    - **26 skeletal components per plane.** Each one gets its own ray-tracing structure that is updated every frame, and all are set to "always tick pose and refresh bones". The 24 rockets need no skinning while they sit on the rack.
    - **No reduction anywhere.** Every mesh has one LOD, Nanite is off and Ray Tracing Min LOD is 0. Ray tracing and skin cache are both on in `DefaultEngine.ini`, and this time it has no local overrides.
    - **The engine mesh is the biggest single item.** At 2.67M triangles it is a prime candidate for the same reduction we did on the B-25.
    - **The construction script likely does heavy work, but I haven't confirmed it.** The graph contains "Assign correct SKM", `CreateDynamicMaterialInstance`, `AddComponent` (propeller blades) and Niagara setup; one spawn produces 52 components, including 4 Niagara systems and a timeline. If the mesh swap runs in the construction script, every rebuild re-initialises a 943k-triangle skinned mesh, its skin cache and its ray-tracing structure. A rebuild happens on each property change, actor move or Sequencer respawn of a spawnable. That matches "stutters every time it's animated". I couldn't trigger a rebuild headlessly, so this needs opening the graph to check.
    - **Gameplay systems on Tick.** The rocket, bomb and gun systems run on Tick, and the graph also has `FindControlRigs`, `DrawDebugLine` and `PrintString` calls. The bomb system looks copied from a B-24 blueprint.
    
    The headless spawn took only 0.056 s of CPU. So the freeze is probably on the GPU side (skin cache, ray-tracing rebuilds, Niagara), which I couldn't measure without a GPU render.
    
    ## Suggested fixes, cheapest first
    
    1. **Broken variants:** either point them at the new `S_GunData` path and the 0253 AnimBP/Control Rig, or retire them in favour of the main BP's enum. Retiring is simpler if no shot uses them, and none of the three shots I found do.
    2. **Rockets:** make the 24 rockets static meshes, and swap in a skeletal mesh only at launch.
    3. **Engine and hull:** build reduced versions of the engine and hull and an `_Optimised` BP, using the same steps as the B-25.
    4. **Construction script and Tick:** move the mesh/material swap out of the construction script, or guard it so it only runs when the enum actually changes. Strip the debug draw/print nodes, and stop Tick in the editor.
